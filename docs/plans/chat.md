# План: общий чат и личные сообщения (MineDed 1.3.0)

Статус: план, не начато. Решения владельца от 2026-10-27 зафиксированы ниже.

## Что получает пользователь

- Вкладка «Чат» в боковом меню. Доступ только с аккаунтом «Мой сервер» (Drasl).
- **Общий чат** для всех пользователей. Мат и оскорбления запрещены.
- **Личные сообщения** между любыми двумя пользователями. Мат и оскорбления не фильтруются.
- В обоих: текст, фото и скриншоты, файлы до **10 МБ**.
- Профиль игрока: ник, скин в 3D, статус (в сети / в игре / в комнате), кнопки «Написать», «Пригласить в комнату».
- Приглашение в комнату — карточка в чате с кнопкой «Войти» (ссылка `mineded://join/<код>`).
- **Поделиться сборкой** в личных: карточка «Fabric 1.21.1, N модов — Попробовать». Получатель
  ставит её одной кнопкой, включая локальные моды отправителя.
- История хранится **вся и всегда**, фото и файлы тоже.

## Решения владельца

| Вопрос | Решение |
|---|---|
| История | Хранить всё, бессрочно, в сжатом виде |
| Вложения | Фото, скриншоты, файлы, до 10 МБ, бессрочно |
| Личные сообщения | Есть, хранятся так же, как общий чат |
| Сборка в личных | Есть, с локальными модами отправителя |
| Модераторы | Только владелец. Брат — обычный игрок |
| Мат | Запрещён в общем чате, разрешён в личных |
| Оскорбления | Запрещены в общем чате, разрешены в личных |

## Архитектура

### Сервер (`server/hub`, server-ops)
- Хранилище: **SQLite (WAL)** в отдельном томе `hub_chat`. Таблицы: `messages` (id, channel, author uuid,
  created_at, kind, body zstd-сжатый, attachment ids, edited/deleted), `channels` (общий + пары для личных),
  `attachments` (sha256, size, mime, path, thumb), `mutes`/`bans`, `reports`, `blocks`.
- Сжатие текста: zstd со словарём, обученным на первых сообщениях. Оценка: ~200 Б на сообщение → ~60 Б
  после сжатия; 1 млн сообщений ≈ 60 МБ. Текст хранится годами без проблем.
- Файлы: на диске по sha256 (одинаковые файлы хранятся один раз). Фото перекодируются в WebP (качество ~85)
  плюс превью 320 px; оригинал до 10 МБ сохраняется только для файлов, не для фото.
- Реальное время: WebSocket `/api/v1/chat/ws` (авторизация Bearer Drasl, как остальные `/me`), REST для истории
  (пагинация курсором), загрузки файлов (`POST /chat/files`, multipart, лимит 10 МБ), профилей и модерации.
- Присутствие: онлайн / в игре / в комнате (лаунчер сообщает сам, в WS).
- Резервные копии: ежедневный бэкап SQLite (`.backup`) + файлов (rsync/архив) — **куда-то кроме этого VPS**.

### Модерация (только общий чат)
- Фильтр мата и оскорблений на сервере перед публикацией: нормализация (регистр, ё→е, латиница-двойники,
  повторы букв, разделители «х.у.й»), словарь корней русского мата и оскорблений. Сообщение не публикуется,
  автор видит «Сообщение нарушает правила чата».
- Кнопка «Пожаловаться» на сообщение → очередь жалоб у владельца.
- Инструменты владельца (роль `admin` = владелец по UUID в конфиге hub): удалить сообщение, мут на 1 ч / 1 д /
  навсегда, бан в чате, просмотр жалоб.
- В личных — без фильтра, но любой может **заблокировать** собеседника (тот не сможет писать).

### Лаунчер
- Контракт (lead): типы `ChatMessage`/`ChatChannel`/`Attachment`/`Presence`/`Profile`, сервис `ChatService`
  (подключение, история, отправка, загрузка файлов, профили, жалобы, блок, модерация), события в UI.
  OpenAPI `server/openapi/hub.yaml` — новые пути.
- net: клиент WS с переподключением, очередь отправки, загрузка файлов через `lc_http`, кэш истории на диске.
- ui: вкладка «Чат» (общий + список личных), виртуализированная лента, вложения (превью, просмотр, сохранение),
  профиль игрока, приглашение в комнату, карточка сборки, панель модерации для владельца, уведомления.
- Поделиться сборкой: отправитель экспортирует `.mrpack` (как для комнат) и прикладывает его к сообщению.
  Сборки с локальными модами обычно больше 10 МБ → для `.mrpack` отдельный лимит (см. вопросы).

## Порядок работ (каждый пункт — отдельная ветка, по готовности — мерж)

1. lead: контракт (OpenAPI + типы + трейт) — 1 короткий заход.
2. server-ops: хранилище, WS, REST, файлы, фильтр, модерация, бэкап; деплой на VPS.
3. net: клиент чата в лаунчере.
4. ui: вкладка, профиль, вложения, модерация, приглашения.
5. Полная проверка, релиз 1.3.0, пост в канал.

Оценка: размер как у 1.1.0. Начинать в начале недели, когда есть лимит.

## Дополнения владельца (2026-10-27)

Принцип — как в Telegram: облачная история, всё доступно с любого устройства после входа.

- **Сборки в личных — напрямую P2P**, не через сервер: в сообщении карточка сборки, файл `.mrpack` с локальными
  модами передаётся напрямую, когда оба в сети (переиспользуем pack-stream из комнат 1.2.1). Если отправитель
  не в сети — карточка показывает «Отправитель не в сети, попробуйте позже».
- **Начать личный чат:** из профиля игрока (клик по нику в общем чате) или через **поиск пользователей** по нику.
- **Друзья:** заявка в друзья → принять/отклонить, список друзей с онлайн-статусом, удалить из друзей.
- **Конфиденциальность** (настройки аккаунта):
  - кто может писать в личные: все / только друзья / никто;
  - кто может приглашать в комнаты: все / только друзья;
  - кто видит мой статус «в сети / в игре»: все / только друзья / никто;
  - кто может добавлять в друзья: все / никто.
- **Синхронизация:** при входе в аккаунт на любом ПК подгружается вся история личных чатов и общего чата
  (лента подгружается порциями при прокрутке, вложения — по запросу). Непрочитанные считаются на сервере.
- **Диск:** не экономим жёстко, но сервер следит за заполнением: при 80 % — уведомление владельцу (в Telegram-бот
  и в лог), при 95 % — новые вложения временно не принимаются. Решение владельца — докупить диск.

## Бэкап и переполнение диска (2026-10-27)

- **Бэкап — на домашний сервер владельца** (место есть): ежедневно SQLite `.backup` + новые вложения
  (инкрементально, rsync поверх SSH, ключ только для записи в одну папку). Проверка восстановления раз в месяц.
- **Диск VPS переполнен (≥ 95 %):** новые вложения не принимаются, текст продолжает работать. Администратор
  видит в лаунчере плашку: «Диск сервера переполнен. Переписка не пострадала, полная копия — на домашнем
  сервере». Кнопки:
  - «Перенести на новый диск» — после того как владелец докупил диск у хостера: сервер переносит данные
    на новый том и включает приём файлов;
  - «Перенести в файлообменник» — вложения уезжают во внешнее хранилище (S3-совместимое: R2 / B2),
    в БД меняются ссылки.
  Операции идут как задачи с прогрессом, исходные данные удаляются только после проверки копии.
- **Уведомления владельцу в Telegram** (бот MineDed, личные сообщения владельцу): 80 % диска, 95 % диска,
  ошибка бэкапа, новые жалобы в чате. Telegram ID владельца хранится **только на сервере** (`.env`).

## Админ-панель в лаунчере

- Видна только пользователям с ролью. Обычные игроки её не видят (и сервер отказывает им на всех admin-API).
- **Роли:**
  - `admin` — администратор Drasl (флаг `isAdmin` в Drasl, сервер проверяет сам). Всё: модерация, назначение
    и снятие модераторов, жалобы, баны, состояние сервера (диск, бэкап), переносы данных.
  - `moderator` — назначает admin. Только модерация общего чата: удалить сообщение, мут до 1 суток, жалобы.
    Не может банить навсегда, назначать модераторов и трогать сервер.
- **Никаких ников, UUID и Telegram ID владельца в репозитории.** Роль admin берётся из Drasl во время работы,
  модераторы хранятся в БД hub, секреты — в `.env` на сервере.
- Разделы: Модерация (жалобы, мут/бан, удалённые сообщения), Пользователи (поиск, роли, инвайты Drasl),
  Сервер (диск, бэкап, плашки, переносы).
