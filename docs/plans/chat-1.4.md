# План: 1.4.0 — лайтбокс, онлайн-счётчик, гостевые аккаунты

Статус: в работе с 2026-10-30. Решения владельца зафиксированы ниже.

## Что получает пользователь

1. **Полноэкранный просмотр фото** — клик по превью в чате открывает фото на весь экран, с закрытием по Esc/фону и кнопкой «Сохранить».
2. **Счётчик онлайна** — видно, сколько людей сейчас в лаунчере (любой тип аккаунта). Публично — только число; список имён — админам.
3. **Гостевой доступ оффлайн-аккаунтов** — оффлайн-ник входит в чат как гость: читает общий чат, переписывается в личных, но **не** пишет в общий чат и **не** добавляет друзей. Комнаты по-прежнему доступны всем типам аккаунтов без изменений.

## Решения владельца (2026-10-30)

| Вопрос | Решение |
|---|---|
| Вход оффлайн-аккаунтов | Гостевой токен: hub выдаёт ограниченный токен оффлайн-нику, ник виден как «гость» |
| Что можно гостю | Чтение общего чата; личные — только с теми, кто уже у него в друзьях |
| Что нельзя гостю | Писать в общий чат, добавлять в друзья |
| Счётчик | Считаем все лаунчеры (любой аккаунт); публично — число, имена — админам |
| Комнаты | Без изменений: оффлайн и серверные аккаунты вместе, как сейчас |

## Архитектура

### Онлайн-счётчик (hub)
- `POST /api/v1/presence/beat` — без авторизации; тело `{ "clientId": <uuid>, "kind": "offline"|"yggdrasil" }`.
  Rate limit по IP; `clientId` — uuid v4, длина ограничена; TTL присутствия 120 с, тик раз в 60 с.
- `GET /api/v1/presence` — публично: `{ "online": <u32> }`.
- `GET /api/v1/chat/admin/presence` — только админ: `{ "online": <u32>, "clients": [{ "name": <строка|null>, "kind": ..., "since": <rfc3339> }] }`.
- Имена для админа берутся только у тех, кто авторизован в чате (гость/серверный аккаунт); анонимные лаунчеры — как `anonymous`.

### Гостевой доступ (hub)
- `POST /api/v1/chat/guest` — тело `{ "name": "<ник>" }` (валидация ника, 3–16 символов, rate limit по IP).
  Ответ: `{ "token": <секрет>, "user": SocialUser, "expiresAt": <rfc3339> }`, срок 30 дней, хранение в SQLite.
- Гость получает `SocialRole::Guest` в `SocialUser`, отдельный флаг `guest: true`.
- Права на сервере (не в UI): общий чат — только чтение; `send` в общий → `permissionDenied` reason `guestReadOnly`;
  личные — только в каналах, где собеседник уже в друзьях; `add_friend` → `permissionDenied` reason `guestCannotAddFriends`.
- Гостю доступен WebSocket: события общего чата и его личных каналов.
- Ник гостя помечается в `SocialUser.guest`, чтобы UI показывал «гость» и не давал писать в общий чат.

### Лайтбокс (ui)
- Компонент `PhotoViewer`: полноэкранный слой, фото по центру (`object-contain`), Esc/клик по фону — закрыть,
  кнопки «Сохранить» и «Закрыть», фокус-трап, без блокировки прокрутки страницы под ним.
- Открывается кликом по превью картинки; для не-картинок поведение прежнее (скачивание).

## Порядок работ

1. **contract (lead)**: типы `PresenceSummary`, `PresenceClient`, `SocialRole::Guest`, поле `SocialUser.guest`,
   методы `ChatService::guest_login`, `PresenceService`; записи в `docs/CONTRACTS.md`; `bindings.ts` регенерацией.
2. **server-ops**: hub — `/presence`, `/presence/beat`, `/chat/admin/presence`, `/chat/guest`, права гостя, тесты.
3. **net**: lc-chat — гостевой логин, права в клиенте, heartbeat счётчика (в lc-http или в src-tauri).
4. **ui**: лайтбокс, бейдж онлайна в шапке чата и на экране «Играть», состояния «гость» (чтение, без отправки в общий).
5. **qa**: ревью, тесты прав (гость не пишет в общий, не добавляет друзей, читает личные), счётчик не обходится подделкой clientId.
6. **release**: версия 1.4.0, CHANGELOG, карточка, тег.

## Риски

- Гость не подтверждён: возможен флуд личными сообщениями друзьям и много «гостей» с одного IP → лимиты по IP и по токену,
  репорты и мут работают и для гостей.
- Счётчик легко накрутить с одного клиента → считаем уникальные `clientId` за TTL и ограничиваем число с одного IP;
  цифра честная «сколько лаунчеров на связи», а не «сколько людей».
- Гостевые токены — долгоживущий секрет: хранение только в keyring лаунчера, отзыв через админ-панель (бан/мут).
